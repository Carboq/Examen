# Simulacro de examen — Práctica 4 (variante)

> Ejercicio de ensayo. No es el enunciado oficial: reproduce la Práctica 4 con
> cambios pequeños, como los que puede introducir el profesor el día del examen.

## Supuestos

- Proxmox VE 8 en el laboratorio, con la interfaz web y acceso root.
- Red de la práctica: `192.168.50.0/24`, puerta de enlace `192.168.50.1`,
  bridge `vmbr1`.
- Tres VM Debian 12: `web1` (201), `web2` (202) y `app` (203).
- Tiempo: **90 minutos**.
- Se puede usar una **plantilla Debian 12** (ID 9000) o, si no existe,
  instalar una VM y clonarla.

Si el laboratorio usa otro segmento o bridge, cambia los valores; lo importante
es el procedimiento.

## Enunciado del simulacro

Monta la infraestructura de la Práctica 4 con estos cambios respecto al guion:

| VM | ID | IP | Servicio |
|---|---|---|---|
| `web1` | 201 | `192.168.50.11` | Apache. Página con asignatura, nombre, IP y **fecha del día**. |
| `web2` | 202 | `192.168.50.12` | Apache. Misma página, con el texto **«Servidor 2»**. |
| `app` | 203 | `192.168.50.13` | MariaDB + Flask + nginx. La base de datos **solo** acepta conexiones desde `app`. |

Requisitos:

- 2 vCPU, 2048 MB de RAM y 32 GB de disco por VM, disco SCSI y NIC `virtio`.
- MAC reservada del laboratorio, fijada **antes** del primer arranque.
- La aplicación Flask debe responder en `/` y en `/salud`, y `/salud` debe
  devolver `{"estado":"ok","servicio":"icdapp","productos":N}`.
- La base de datos no debe aceptar conexiones desde `web1` ni `web2`.

### Cambios respecto a la práctica original

1. La red pasa de `192.168.100.0/24` a `192.168.50.0/24`.
2. Los IDs pasan de 101–103 a 201–203.
3. `/salud` añade el campo `servicio`.
4. La base de datos se restringe a la IP de `app` (no a toda la red).
5. La página de los servidores web incluye la fecha.

## Plan de 90 minutos

| Minutos | Fase |
|---|---|
| 0–5 | Leer el enunciado, escribir la tabla y comprobar el entorno. |
| 5–15 | Crear o clonar las tres VM. |
| 15–25 | Red: IP, hostname y pruebas de ping. |
| 25–35 | Apache en `web1` y `web2`. |
| 35–70 | MariaDB + Flask + systemd + nginx en `app`. |
| 70–82 | Validación. |
| 82–90 | Evidencias (capturas). |

Si instalas Debian desde ISO en lugar de clonar, añade 20–30 minutos. En ese
caso, quita `web2` o reduce la validación: la aplicación vale el 80 % de la nota.

## Fase 0. Antes de tocar nada (5 min)

1. Escribe la tabla de direcciones en papel. No empieces a crear VM sin ella.
2. Comprueba el entorno en el host:

```bash
qm list
pvesm status
ip -br link
pvesm list local | grep -i iso
```

3. Localiza la plantilla de Debian, si existe:

```bash
qm list | grep -i plantilla
# o busca el ID que te indique el profesor
```

4. Anota las MAC reservadas que te correspondan.

## Fase 1. Crear las VM (10 min con plantilla)

### Ruta A — hay plantilla (recomendada)

```bash
qm clone 9000 201 --name web1 --full --storage local-lvm
qm clone 9000 202 --name web2 --full --storage local-lvm
qm clone 9000 203 --name app  --full --storage local-lvm

qm set 201 --cores 2 --memory 2048 --net0 virtio,bridge=vmbr1,macaddr=<MAC1>
qm set 202 --cores 2 --memory 2048 --net0 virtio,bridge=vmbr1,macaddr=<MAC2>
qm set 203 --cores 2 --memory 2048 --net0 virtio,bridge=vmbr1,macaddr=<MAC3>

qm start 201 202 203
```

Si la plantilla tiene menos de 32 GB:

```bash
qm resize 201 scsi0 32G
qm resize 202 scsi0 32G
qm resize 203 scsi0 32G
```

### Ruta B — no hay plantilla

Crea solo `web1` con el script, instala Debian y clona:

```bash
cp p4/vms.conf.example p4/vms.conf
# deja una sola línea:
# web1|201|2048|2|32|vmbr1|<MAC1>|local:iso/debian-12-netinst.iso
./icd.sh p4 create --file p4/vms.conf
```

Instala Debian en `web1` desde la consola (IP `.11`, SSH y servidor web).
Después, con la VM apagada, quita la ISO y arranca del disco:

```bash
qm shutdown 201
qm set 201 --boot order=scsi0 --delete ide2
qm clone 201 202 --name web2 --full
qm clone 201 203 --name app  --full
qm set 202 --net0 virtio,bridge=vmbr1,macaddr=<MAC2>
qm set 203 --net0 virtio,bridge=vmbr1,macaddr=<MAC3>
qm start 201 202 203
```

En cada clon, antes de nada, cambia la identidad:

```bash
hostnamectl set-hostname web2          # o app
sed -i 's/web1/web2/g' /etc/hosts      # o app
rm -f /etc/machine-id && systemd-machine-id-setup
rm -f /etc/ssh/ssh_host_* && dpkg-reconfigure -f noninteractive openssh-server
```

> Si cambias la IP por SSH, perderás la conexión. Hazlo desde la consola de
> Proxmox o con `nohup`.

## Fase 2. Red (10 min)

En cada VM, desde la consola:

```bash
ip a                     # confirma que la interfaz es ens18
```

Edita `/etc/network/interfaces` (o el fichero de `interfaces.d` que use la
plantilla):

```bash
auto ens18
iface ens18 inet static
    address 192.168.50.11
    netmask 255.255.255.0
    gateway 192.168.50.1
    dns-nameservers 192.168.50.1
```

Aplica y comprueba:

```bash
systemctl restart networking
ip a
ping -c 3 192.168.50.1
ping -c 3 192.168.50.12
ping -c 3 192.168.50.13
```

Si `ping` entre VM falla, revisa que las tres estén en `vmbr1` y que no haya
dos con la misma IP (típico tras clonar).

## Fase 4. Aplicación en app (35 min)

### 4.1 MariaDB

```bash
apt install -y mariadb-server
systemctl enable --now mariadb

# Escuchar en la red (no solo en localhost)
sed -i 's/^bind-address.*/bind-address = 0.0.0.0/' /etc/mysql/mariadb.conf.d/50-server.cnf
systemctl restart mariadb

mariadb <<'SQL'
CREATE DATABASE icd;
CREATE USER 'icd'@'192.168.50.13' IDENTIFIED BY 'icd2026';
GRANT ALL PRIVILEGES ON icd.* TO 'icd'@'192.168.50.13';
FLUSH PRIVILEGES;
SQL

mariadb icd <<'SQL'
CREATE TABLE productos (
  id INT AUTO_INCREMENT PRIMARY KEY,
  nombre VARCHAR(80) NOT NULL,
  precio DECIMAL(8,2) NOT NULL,
  stock INT NOT NULL
);
INSERT INTO productos (nombre, precio, stock) VALUES
('Teclado', 25.50, 10),
('Ratón', 15.00, 20),
('Monitor', 120.00, 5),
('Disco SSD', 80.00, 8),
('Memoria RAM', 45.00, 12);
SQL
```

Comprueba desde `app`:

```bash
mariadb -h 192.168.50.13 -u icd -picd2026 icd -e 'SELECT COUNT(*) FROM productos;'
```

### 4.2 Flask

```bash
apt install -y python3-flask python3-pymysql gunicorn
mkdir -p /opt/icdapp
cat > /opt/icdapp/app.py <<'EOF'
from flask import Flask, jsonify, render_template_string
import pymysql

app = Flask(__name__)
DB = dict(host="192.168.50.13", user="icd", password="icd2026",
          database="icd", cursorclass=pymysql.cursors.DictCursor)

def filas():
    c = pymysql.connect(**DB)
    try:
        with c.cursor() as q:
            q.execute("SELECT id, nombre, precio, stock FROM productos ORDER BY id")
            return q.fetchall()
    finally:
        c.close()

PLANTILLA = """<!doctype html>
<html lang="es"><head><meta charset="utf-8"><title>ICD - app</title></head>
<body>
  <h1>Infraestructura Informática para Centros de Datos</h1>
  <p>Estudiante: Carles Luis Boquera</p>
  <p>Servidor: app (192.168.50.13)</p>
  <table border="1">
    <tr><th>ID</th><th>Nombre</th><th>Precio</th><th>Stock</th></tr>
    {% for f in filas %}
    <tr><td>{{ f.id }}</td><td>{{ f.nombre }}</td><td>{{ f.precio }}</td><td>{{ f.stock }}</td></tr>
    {% endfor %}
  </table>
</body></html>"""

@app.route("/")
def index():
    return render_template_string(PLANTILLA, filas=filas())

@app.route("/salud")
def salud():
    return jsonify(estado="ok", servicio="icdapp", productos=len(filas()))

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)
EOF
```

Prueba rápida en primer plano:

```bash
cd /opt/icdapp
python3 app.py
# en otra consola:
curl -s http://127.0.0.1:5000/salud
# Ctrl+C en la primera consola para parar y pasar a systemd
```

### 4.3 Servicio systemd

```bash
cat > /etc/systemd/system/icdapp.service <<'EOF'
[Unit]
Description=Aplicacion Flask ICD
After=network.target mariadb.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/icdapp
ExecStart=/usr/bin/gunicorn --workers 2 --bind 127.0.0.1:5000 app:app
Restart=always

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now icdapp
systemctl status icdapp --no-pager
```

### 4.4 nginx

```bash
apt install -y nginx

cat > /etc/nginx/sites-available/icdapp <<'EOF'
server {
    listen 80;
    server_name _;
    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
EOF

ln -sf /etc/nginx/sites-available/icdapp /etc/nginx/sites-enabled/icdapp
rm -f /etc/nginx/sites-enabled/default
nginx -t && systemctl reload nginx
```

Comprueba:

```bash
curl -s http://localhost/salud
curl -s http://localhost | head -20
```

## Fase 5. Validación (12 min)

Desde `web1`:

```bash
curl -s http://192.168.50.12 | head -5
curl -s http://192.168.50.13 | head -10
curl -s http://192.168.50.13/salud
```

Salida esperada de `/salud`:

```json
{"estado":"ok","productos":5,"servicio":"icdapp"}
```

Desde `web2`, comprueba que la base de datos **no** acepta la conexión:

```bash
apt install -y mariadb-client
mariadb -h 192.168.50.13 -u icd -picd2026 -e 'SELECT 1'
```

Debe fallar con `Access denied for user 'icd'@'192.168.50.12'`.

Estado de los servicios:

```bash
systemctl is-active apache2 icdapp nginx mariadb
```

En `web1`/`web2` no existe `icdapp` ni `nginx`; ejecuta el comando solo con los
servicios que tenga cada máquina.

## Si algo falla

| Síntoma | Causa probable | Solución |
|---|---|---|
| Dos VM con la misma IP | Clon sin cambiar la red | Cambia la IP y reinicia `networking`. |
| `502 Bad Gateway` en nginx | `icdapp` no está corriendo | `systemctl status icdapp`, `journalctl -u icdapp`. |
| `Access denied` desde `app` | Usuario creado para otro host | Crea `'icd'@'192.168.50.13'` o conecta a `127.0.0.1`. |
| La BD no escucha fuera | `bind-address = 127.0.0.1` | Cámbialo a `0.0.0.0` y reinicia MariaDB. |
| Apache y nginx chocan en el puerto 80 | Ambos instalados en `app` | No instales Apache en `app`; usa solo nginx. |
| La MAC no es la reservada | Se arrancó antes de fijarla | Cambia `net0` y reinicia; si hay DHCP, renueva. |
| `ping` entre VM falla | Bridges distintos | Comprueba `net0` de las tres en `vmbr1`. |

## Qué práctica esto

- Leer un enunciado con cambios y traducirlo a una tabla de direcciones.
- Crear o clonar VM y fijar MAC/IP antes de arrancar.
- Instalar y verificar Apache, MariaDB, Flask, systemd y nginx.
- Validar desde otra máquina, no solo desde `localhost`.
- Restringir la base de datos a la máquina de aplicación.

## Atajo: script de servicios

El repositorio incluye `p4/servicios.sh`, que ejecuta los bloques de las fases
3 y 4 dentro de cada VM:

```bash
# Copia el repositorio a la VM (desde el host o desde un USB) y entra en él:
sudo ./p4/servicios.sh web1
sudo ./p4/servicios.sh web2
sudo ./p4/servicios.sh app
```

El script es idempotente y admite `--ip`, `--db-host`, `--db-pass`, `--student`
y `--no-apt`. No instala Debian ni cambia la IP: eso sigue siendo manual. La
ventaja es que el examen queda en **crear la VM + ejecutar un comando por VM**.
